# Benchmarks M1

Máquina: Apple M3, 16 GB RAM, macOS 26.6.2 — build `--release`.

| Medida | Valor |
|---|---|
| RSS en reposo, 1 terminal | 105,4 MB (run 1: 107 904 KB) / 105,6 MB (run 2: 108 160 KB) |
| `cat` 78 MB en colmena | 1,10 s (run 1) / 1,13 s (run 2) |
| `cat` 78 MB en Terminal.app | ___ (pendiente, medir a mano) |
| RSS tras el `cat` (scrollback 10 000) | 105,7 MB (run 1: 108 192 KB) / 105,6 MB (run 2: 108 160 KB) |
| ¿La UI se congeló durante el `cat`? | ___ (pendiente, medir a mano) |

Objetivo del spec (§10, medido en M2/M4): < 150 MB con 5 terminales y 2 sesiones de Claude.

## Método

- El archivo de prueba es `seq 1 7000000 > /tmp/colmena-55mb.txt`; pese al nombre pesa 78 222 180 bytes
  (~75 MiB), no 55 MB.
- Se lanzó `SHELL=<script> ./target/release/colmena` (alacritty_terminal usa `$SHELL`). El script
  duerme 3 s (reposo), toma un timestamp, hace `cat` del archivo hacia su stdout (el PTY de colmena),
  toma otro timestamp y escribe la diferencia; después `exec sleep 600` para mantener la ventana.
  Los timestamps se toman con `python3 time.time()`.
- RSS con `ps -o rss= -p <pid>` (KB) en reposo y ~1 s después de terminar el `cat`.
- Piso de referencia: `cat` del mismo archivo a `/dev/null` tarda 0,026 s, de modo que los ~1,1 s
  de colmena incluyen el parseo y el volcado a la grilla. Este tiempo mide cuándo `cat` terminó de
  escribir al PTY (contrapresión del lector), no cuándo la ventana terminó de pintar; puede diferir
  de un `time cat` a mano.
- No se movió ni redimensionó la ventana durante la medición (sin acceso al GUI), por eso la fila de
  congelamiento queda pendiente.
- La RSS apenas cambia tras el `cat`: con 10 000 líneas de scrollback el historial es chico frente a
  la base de ~105 MB (GPUI/Metal).
